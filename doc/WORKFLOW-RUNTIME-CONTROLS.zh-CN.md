# 工作流额度、停表与人工续跑

## 平台上限

在「任务工作流」页点击「平台上限」。只有实例管理员或本地隐式管理员可以修改。默认每阶段最多尝试 **5 次**、整条流程默认**不设总时长上限**、同时执行 **2 个阶段**。平台、公司、项目、任务逐层继承，下层只能收紧自动额度；已有明确的更低公司／项目规则不会被升级覆盖。

平台修改只影响之后接入的任务，已有任务保留冻结快照。可以设置已记录费用上限，也可以留空；公司预算始终独立生效。技术范围为每阶段 1–10 次、不限时或显式 1–1440 分钟、并发 1–10、费用留空或 1–1000000 美分。

## 人工验收停表

只有人工审查／验收阶段正在等待，且没有自动阶段运行时，暂停执行计时；并行 Agent 或系统核验仍在运行时继续计时。停表时间写入数据库，服务重启或页面关闭不会丢失。人工提交决定、人工暂停或取消时结算等待时长，不把等待重复计入额度。

时间额度按整条流程的活跃墙钟时间计算，并非所有 Agent 的 CPU 时间之和。暂停和纯人工等待不消耗该额度。正在运行的系统命令仍受自身超时限制。

## 追加额度并续跑

在已暂停或转人工的根任务「任务工作流」面板中：

1. 查看停止原因和保留的尝试证据。
2. 在原因栏填写为何继续，以及已采取的处理措施。
3. 展开「追加额度并续跑」，填写追加次数、分钟，或已有费用上限的增量。
4. 提交后继续同一个根任务；需要返修时生成新的阶段尝试并保留旧证据。曾被暂停的未结束尝试仍沿用原阶段任务。

每次授权保存操作者、原因、时间、增量及额度前后值，界面显示「人工追加记录」。授权可以超过原始自动额度，但累计仍不超过技术范围；不提高并发，不改变验收条件，不解除公司预算、权限、未定价用量或工具配置问题。Agent 不能自行追加。普通恢复不会增加额度；额度仍耗尽时会要求追加。

续跑须使用当前版本号，重复提交或过期页面返回冲突。旧执行进程尚未停止时会要求稍后重试。已经完成或取消的任务不能继续。额度与续跑原子提交，不满足继续条件时不会仅增加额度。

## 无效循环识别的边界

同一阶段连续 **3 次**出现相同失败信号会停止自动返修并转人工：

- 结构化审查：对比产物标识、声明版本、未通过／未验证验收项和发现的问题所属验收项。
- 没有结构化报告：仅对比去除多余空白后的相同错误文本。
- 相同尝试重复回调不累计；成功、不同失败信号或不同产物版本重置连续计数。

这是可核查的重复信号识别，不保证识别所有语义上的无效工作，也不能证明 Agent 声明的产物版本真实变化。人工填写原因后可确认继续，确认写入审计记录；旧失败不会再计一次。次数、时长和费用上限仍是兜底。

## 升级与兼容

新增迁移 `0336_calm_rocket_racer.sql`，只给 `workflow_runs` 添加默认空对象的 `runtime` 列，保存停表、授权和重复失败状态。升级前备份数据库，再按仓库迁移流程应用。旧快照不会重写；旧的人工等待从新引擎首次处理时起开始停表，不追溯补偿升级前的等待。

工作流改进的基线比较使用追加后的有效额度，防止候选流程靠额外资源通过原预算对比。Office、Wiki 和 Agent 登录配置不需要重新安装。

本次工程检查使用隔离临时数据库及模拟唤醒；页面与真实 Agent 流程由使用者验收。


### 工作流不限总时长（2026-11-07）
新工作流出厂默认 `timeoutMinutes: null`，表示不设工作流总时长上限；显式整数 1–1440 表示有限分钟数。省略字段继承上级，null 不可绕过上级显式有限额度。平台时长留空保存 null；公司/项目可选择“不设时长上限”或留空继承。费用、尝试次数、并发、权限、取消、单次工具/运行超时及重复失败保护仍独立生效。数据库以 `deadline_at IS NULL` 表示不限时，命令检查仍使用自己的有限超时与租约，不使用超远日期或反复自动续时。已有配置、任务快照、暂停与到期决定不被追溯改写；升级不会自动恢复旧任务。需要先执行随代码提供的数据库迁移，再运行新版本。
