# 工作流额度、停表与续跑改造

## 范围

- 默认每阶段 5 次、整条流程 180 分钟、并发 2。
- 实例管理员可以在工作流页面修改平台额度；公司和项目继续按继承规则收紧自动额度。
- 只有人工审查／验收在等待、没有自动阶段在运行时停表；并行自动工作仍计时。停表状态持久化，重启后继续保留。
- 操作员可以针对已停止的根任务追加次数、分钟或已记录费用额度，并在原任务上续跑。必须填写原因，使用版本校验，保留冻结快照和所有历史证据；不解除公司预算或权限约束。
- 连续三次相同失败转人工处理。结构化审查按产物版本和未通过验收项识别；无结构化证据时只识别相同错误文本，显示为疑似重复失败，不宣称自动理解所有进展。

## 数据与兼容

在 `workflow_runs` 添加独立运行控制 JSON，存储人工等待计时点、人工授权增量及重复失败记录。旧记录默认空对象。原始任务快照保持不可变。

人工追加只影响当前运行，允许显式超出原自动额度，总额度仍受结构校验范围约束（10 次、1440 分钟、已记录费用上限 10000 美元）。不允许 Agent 自行追加，不自动放宽并发或修改验收标准。

## 检查与交付

增加额度、计时、重复失败、权限和版本冲突的针对性测试。数据库测试使用隔离临时库和模拟唤醒，不连接现有业务库运行测试，不启动真实 Agent。完成构建后备份现有数据库、应用新增迁移、部署新前后端并设置已批准默认值。浏览器与真实工作流由用户验收。
